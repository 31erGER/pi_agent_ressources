## 1. Human Requirement (Original Intent)
> The pi TUI currently shows the *compaction-aware* context (what the inference engine sees, e.g. LM Studio), while the session files on disk keep the *full* conversation. The user wants a **read-only** extension with a `/history` command that toggles the display: `/history` (bare = toggle), `/history full`, `/history context`. In `full` mode the user wants to see the complete conversation in the TUI "just for myself to keep track"; pi must **continue sending the compacted context** to the LLM — nothing about model context, compaction, or session message content may change.

## 2. Technical Architecture & Data Flow
- **Core Mechanism:** Verified in pi 1.5.2 source: the TUI renders `sessionManager.buildContextEntries()` (`dist/modes/interactive/interactive-mode.js`: `renderInitialMessages`, `rebuildChatFromMessages`, compaction event handler), i.e. the post-compaction view; pre-compaction messages are dropped from the display but stay in the session file. There is **no public hook** to make the built-in transcript itself render the full branch (`registerMessageRenderer`/`registerEntryRenderer` only match extension `customType`s). Workable mechanism: append a `custom` session entry (`pi.appendEntry("history-mirror", …)`) — pi core guarantees `custom` entries **never enter model context** — and render it inline in the transcript via `pi.registerEntryRenderer`. The renderer runs once per (entry, expanded) state, but the returned component's `render(width)` runs on every TUI render pass, so the component computes `hidden = getBranch() − buildContextEntries()` **live** and shows exactly the messages currently hidden by compaction (no duplication with the visible transcript).
- **Data / Control Flow:** `/history [full|context]` → command handler sets mode (in-memory + persisted as `custom` entry `history-mode`, last one wins) → in `full` mode ensures a `history-mirror` entry exists on the active branch (`pi.appendEntry` if missing) → TUI render pass → `history-mirror` entry renderer → live component renders hidden messages as theme-aware lines → `ctx.ui.setStatus("history", "full|context")` footer indicator; `session_start` restores mode from entries, `session_compact` re-appends the mirror if it was compacted away, `session_tree` refreshes cached state.
- **Reuse & Conventions:** `ctx.sessionManager.getBranch()/buildContextEntries()/getEntries()` (read-only); `pi.registerCommand` + `getArgumentCompletions`; `pi.registerEntryRenderer` (doc pattern: `Box`/`Text` + `theme`); `pi.appendEntry`; `ctx.ui.setStatus`/`notify`; pi-tui `Container`/`Text`/`Spacer` + `truncateToWidth`; verification workflow from `pi-extension-upgrade-check` skill (pinned `typescript@5.9.2`, `pi-ext-loadtest.mjs`).
- **Acceptance Criteria:**
  1. In a compacted TUI session, `/history full` shows an inline block listing every message currently hidden by compaction (user/assistant text in full, tool results collapsed to `tool: name → N lines`), and it updates after a further compaction.
  2. `/history context` (or bare `/history` while in `full`) removes the block; the transcript otherwise matches pi's default rendering (at most one spacer line differs).
  3. Model context is provably unchanged: after toggling, the session file gained only `custom` entries (`history-mode`, `history-mirror`); no message/compaction/context_edit entries were created or modified.
  4. Mode survives `/resume`/restart: last `history-mode` entry wins.
  5. `node --test test/` passes; `pi-ext-loadtest.mjs` prints `ALL LOADED`; `tsc` (pinned 5.9.2) reports 0 errors.

## 5. Negative Knowledge (Guardrails & Taboos)
- **Do NOT touch:** pi release files under `~/.pi/agent/install/`, other extensions in `~/.pi/agent/extensions/`, session JSONL files directly (the extension may only append via `pi.appendEntry`), `~/.pi/agent/node_modules` symlinks, anything in the git repo outside this project directory + the one new extension file.
- **Known Pitfalls / Failed Approaches:**
  - `custom_message` entries (`pi.sendMessage`) **do participate in LLM context** — using them to display history would pollute what LM Studio receives. Only `custom` entries (`pi.appendEntry`) are safe.
  - There is **no API to delete session entries** → stale `history-mirror` entries accumulate once a later compaction compacts them away. Acceptable (invisible, zero context impact); re-append a fresh mirror on `session_compact` instead.
  - The entry renderer function is invoked only on construction/expand/invalidate — live updates must come from the inner component's `render(width)` (called every TUI render pass); cache lines keyed on `(width, leafId, hiddenCount, mode, expanded)` to keep rendering cheap.
  - The mirror block renders at the position where it was appended, **not** at the original chronological positions of the hidden messages (documented UX trade-off).
  - Node 26 type-stripping: `src/` and `test/` must use erasable TS only (no enums, namespaces, parameter properties).
  - Extension imports are limited to the jiti aliases: `@earendil-works/pi-coding-agent` and `@earendil-works/pi-tui` (+ node builtins).
  - Pin `typescript@5.9.2` for tsc — newer tsc removed `baseUrl`/non-relative `paths` and breaks the tsconfig template.
  - In non-TUI modes (`print`/`json`/`rpc`) the command must no-op gracefully (`ctx.hasUI` / `ctx.mode === "tui"` guards); entry rendering is TUI-only anyway.
