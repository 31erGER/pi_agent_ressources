## 1. Human Requirement (Original Intent)
Per-model reasoning (thinking) effort options in the pi TUI: each LM Studio model should expose its own array of efforts, togglable with shift+Tab; the API call to the LM Studio server must send the matching effort value; options must update when a session starts, when models are (re)loaded, or when a model is manually changed — with **no periodic polling**, prioritizing pi's native features. If the LM Studio API already reports a model's possible reasoning efforts, those should drive the options.

**Research result (done, 2026-11-04):**
- Pi already delivers the whole per-model mechanism natively: model `reasoning` flag + `thinkingLevelMap` (null = level hidden; `xhigh`/`max` only when explicitly mapped) → shift+Tab (`app.thinking.cycle`) re-derives the available levels from the *current* model on every keypress (`agent-session.js:2156` `cycleThinkingLevel` → `getSupportedThinkingLevels`, pi-ai `models.js:694`); model switches natively clamp the level; openai-completions sends the mapped value as `reasoning_effort` when `compat.supportsReasoningEffort`.
- The existing `extensions/lmstudio.ts` already wires this: dynamic model discovery, `efforts.json` auto-entries (`ensureModels`), per-model `thinkingLevelMap`, and refreshes at exactly the native moments the user named (startup registration, `/model` open, `/lmstudio`, `/reload`).
- **The LM Studio 0.4.28 API does NOT expose per-model supported reasoning efforts** (probed live on the running server: `/api/v0/models`, `/api/v0/models/{id}`, `/v1/models` — model object has only `id/object/type/publisher/arch/compatibility_type/quantization/state/max_context_length/loaded_context_length/capabilities`; `capabilities` carries e.g. `tool_use`, no effort data). → `efforts.json` remains the source of truth for the per-model effort array; the "use API data if present" branch is therefore not implemented (would be pure speculation about a field that doesn't exist).

## 2. Technical Architecture & Data Flow
- **Core Mechanism:** The only new runtime surface is a small `/efforts` TUI command in a new extension: it manages the per-model effort array in the existing `efforts.json` (set: listed levels keep their existing value or `DEFAULT_ENTRY` value, unlisted → null; show: current toggleable list). It then triggers the **existing native refresh** (`ctx.modelRegistry.refresh({providers:["lmstudio"], force:true, allowNetwork:true})` re-runs the existing `refreshModels` → new model objects with fresh `thinkingLevelMap`) and swaps the active model object via `pi.setModel(fresh)` — guarded so it fires only when the current model's option set actually changed (side effect: one `model_change` session entry; `setModel` also re-clamps the level). After that, 100% native: shift+Tab cycles the new set, model switches clamp, and the provider sends the mapped `reasoning_effort`.
- **Data / Control Flow:** `/efforts off,low,high,xhigh` -> (pure) `parseLevelsArg` -> (existing pure) write `efforts.json` -> native `refreshModels` (existing `extensions/lmstudio.ts`) -> registry snapshot rebuild -> guarded `pi.setModel(fresh)` -> native shift+Tab cycle + native `reasoning_effort` mapping. External `efforts.json` edits need no watcher: they apply at the next native refresh (session start / `/model` / `/lmstudio`), which is exactly the cadence the user specified.
- **Reuse & Conventions:** `projects/lmstudio/lmstudio-efforts.ts` (`PI_LEVELS`, `DEFAULT_ENTRY`, `loadEfforts`, `ensureModels`, `effortsFileUrl`); `extensions/lmstudio.ts` refresh + `/lmstudio` command pattern (untouched); sibling e2e harness `projects/lmstudio/e2e.mjs` (mock LM Studio server, `PI_*` env stripping, `/tmp` child cwd, captured `reasoning_effort` payloads); e2e control channel = pi RPC mode (`pi --mode rpc`, JSONL; commands `get_state`, `get_available_thinking_levels`, `set_model`, `prompt` — extension commands execute via `prompt`).
- **Acceptance Criteria:**
  1. `/efforts` (no args) on an LM Studio reasoning model shows its current toggleable level list (and the efforts file path); clear notification for non-LM-Studio or non-reasoning models.
  2. `/efforts off,low,high,xhigh` changes the active model's shift+Tab set to exactly that list **without restart** (proven via RPC `get_available_thinking_levels` before/after).
  3. After a set, the next chat request sends the mapped value as `reasoning_effort` (mock server capture); the file on disk holds the array (unlisted levels `null`).
  4. A model that appears on the LM Studio server is picked up at the next native refresh (`/lmstudio`) with an auto-created default entry; selecting it yields the full default option set (native path, e2e-proven).
  5. Invalid level tokens are rejected with the valid list shown; `efforts.json` is left unmodified.
  6. Scope guard: `git status` shows no changes to `extensions/lmstudio.ts` or anything under `projects/lmstudio/`.

## 5. Negative Knowledge (Guardrails & Taboos)
- **Do NOT touch:** `extensions/lmstudio.ts`, anything under `projects/lmstudio/` (incl. `efforts.json` at rest — it is written only at runtime by pi), the pi runtime under `install/`, any other extension.
- **Do NOT add:** polling timers, `fs.watch`, lifecycle hooks (`session_start`/`session_shutdown`) — the extension holds no background resources (explicit user decision: native refresh moments are the update cadence).
- **Known Pitfalls / Failed Approaches:**
  - pi's built-in `DEFAULT_THINKING_LEVEL` is `"medium"` — e2e assertions on the off/low paths must set the level explicitly.
  - RPC/print child processes must strip all `PI_*` env vars (else they resume the live session) and run from a `/tmp` cwd (project trust prompt).
  - `ModelRuntime.registerProvider` (re-registration) resets the snapshot to the config's **static** `models` list — do NOT re-register to update models; use `refresh({force:true})` + guarded `pi.setModel`.
  - `pi.setModel` appends a `model_change` session entry unconditionally — hence the `optionsDiffer` guard before calling it.
  - `getSupportedThinkingLevels` semantics: null hides ANY level (incl. `off`); `xhigh`/`max` require an explicit non-null mapping; non-reasoning models only ever expose `["off"]`.
  - If LM Studio's API ever exposes per-model effort support, the natural hook is the existing `refreshModels` (merge server data into `thinkingLevelMap`); today the field does not exist, so nothing is implemented for it.
  - efforts.json semantics (existing extension, user confusion 2026-11-04): a **missing** level key is backfilled from `DEFAULT_ENTRY` by `ensureModels` at every refresh (model load!) → level stays VISIBLE; only an explicit **`null`** hides a level and survives backfill. So a hand-written 4-key entry silently becomes 7 visible levels. The TUI way to set an array is `/efforts <list>` (writes explicit nulls). Changing missing→null semantics would require editing the existing `projects/lmstudio` extension (out of scope here) and re-checking `openai-completions.js:621` (`map[level] ?? level` — null would send `reasoning_effort: null`).
