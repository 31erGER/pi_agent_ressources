## 1. Human Requirement (Original Intent)
The `web.ts` pi extension crashes the agent whenever a tool is used and its `fetch` tool secretly routes every URL through the third-party proxy `r.jina.ai` (data exfiltration). Replace it with a safe, working, slightly extended version: `search` via the local SearXNG docker container (localhost:8080), `fetch` that reads pages directly with local HTML→text conversion, plus a block of human-readable configuration variables at the top of the file the user can adjust later. The original malicious file is kept as a backup copy.

## 2. Technical Architecture & Data Flow
- **Core Mechanism:** One extension file registers two tools via `defineTool` (from `@earendil-works/pi-coding-agent`; plain JSON parameter schemas because `@earendil-works/pi-ai`/typebox is not resolvable from the extensions folder — verified). `search` does an HTTP GET to the SearXNG JSON API and formats the top N results; `fetch` does a direct HTTP GET (no proxy) with a timeout, converts HTML to plain text locally (no new dependencies), and truncates to a character limit. All tunables are named constants in a comment-marked config block at the top of the file.
- **Data / Control Flow:** `LLM tool call -> execute(toolCallId, params, signal, onUpdate, ctx) -> HTTP GET (SearXNG or target URL) -> validate/format/convert/truncate -> { content:[{type:"text",text}], details } -> pi` (failures return `{content, details, isError:true}` — never an uncaught exception, never a bare string)
- **Reuse & Conventions:** result shape `{content, details}` per `docs/extensions.md` §Tool Definition; `isError: true` for signaled failures (throw not needed); `label`/`promptSnippet`/`promptGuidelines` fields naming the tool explicitly; conventions from `examples/extensions/hello.ts`; jiti is the loader (transpile only, no type-check) so the test harness is the runtime gate
- **Config block (top of file, per user request):** `SEARXNG_BASE_URL` (default `http://localhost:8080`), `SEARCH_MAX_RESULTS` (default 5), `SEARCH_MAX_RESULTS_LIMIT` (10), `SEARCH_SNIPPET_CHARS` (300), `FETCH_TIMEOUT_MS` (15000), `FETCH_MAX_CHARS` (20000) — each with a one-line comment; every usage below references the constant
- **Acceptance Criteria:**
  1. Loading the extension through jiti (pi's actual loader) registers both tools `search` and `fetch` without error
  2. `search` against live SearXNG returns a correctly shaped result and honors `max_results` (asking for 3 yields exactly 3 entries)
  3. `fetch` on a real HTML page returns extracted plain text, contains no `r.jina.ai` in the request path (no occurrence of "jina" in the file), and truncates at the configured limit with a visible notice
  4. Failure paths (invalid scheme, unreachable host, non-2xx, SearXNG down) return `{isError:true}` results instead of throwing — the session can never crash from a web tool
  5. The config block sits at the top of the file, is human-readable, and every tunable behavior references it
