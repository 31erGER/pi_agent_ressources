## 1. Human Requirement (Original Intent)
The global token counter (footer `Σ↑… Σ↓… (global)`) must reflect **all tokens the GPU ever generated**.
Right now it re-derives its total from the session files under `~/.pi/agent/sessions/` on every pi start/scan.
When a session is nuked (`/nuke` or `/nuke-exit` in `nuke-session.ts`), its file is moved away (here: always to
`~/.pi/agent/discarded-sessions/`, because `trash`/trash-cli is **not installed**), so its tokens silently
disappear from the counter. Fix: at nuke time, persist the session's token totals into
`~/.pi/agent/deleted-session-tokens.json`; the counter adds that ledger to the live session sum.

## 2. Technical Architecture & Data Flow
- **Core Mechanism:** Shared helper module `extensions/shared/deleted-session-tokens.ts` (a *non-extension*:
  pi's discovery skips subdirectories without `index.ts`, verified in `dist/core/extensions/loader.js`
  `discoverExtensionsInDir`/`resolveExtensionEntries`). It owns the JSON ledger format, the one-shot
  whole-file usage summation (`sumSessionUsage`), the atomic upsert writer (`recordDeletedSession`),
  the reader (`readDeletedTotals`), and the reconciler (`reconcileDeletedStore`). Both extensions import it.
- **Ledger format** (`~/.pi/agent/deleted-session-tokens.json`):
  `{ "version": 1, "sessions": [ { "file": "<abs path of nuked .jsonl>", "input": n, "output": n, "deletedAt": "<ISO>" } ] }`
  — upsert keyed by absolute file path (session file names contain a UUID ⇒ path is unique).
  Missing/corrupt file ⇒ treated as empty ledger, never throws. Writes are atomic (tmp file + rename).
- **Data / Control Flow (nuke):** `/nuke|/nuke-exit` → `sumSessionUsage(file)` (file still on disk) →
  `discardSessionFile(file)` (existing trash/fallback move; on throw: nothing recorded, file intact) →
  `recordDeletedSession(file, input, output)` (append/upsert ledger; on throw: error to stderr, tokens lost — logged).
- **Data / Control Flow (counter):** `scanNow()` → `scanner.scan(sessionsDir)` (unchanged incremental scan) →
  `reconcileDeletedStore(scanner.liveFiles)` (drops ledger entries whose file is live again, e.g. restored
  session — prevents double counting) → `deleted = readDeletedTotals()` → footer shows
  `live.input + deleted.input` / `live.output + deleted.output` (one combined Σ, same label).
- **Reuse & Conventions:** `usageOf(entry)` is **moved** from `token-counter.ts` into the shared module
  (identical semantics: assistant `message.usage` + `compaction`/`branch_summary`/`usage` entries), so live
  and nuked totals can never drift. Agent-dir root JSON placement matches existing convention
  (`perf-stats.json`, `usage-stats.json`, `crashes.json`). `getAgentDir()` from
  `@earendil-works/pi-coding-agent` (import works in plain node — verified) with an explicit-dir parameter
  for testability.
- **Acceptance Criteria:**
  1. `node --test test/` passes (unit tests for the shared module + import smoke test of both extensions).
  2. After `/nuke`, `jq '.sessions' ~/.pi/agent/deleted-session-tokens.json` contains an entry whose
     input/output match the nuked session file's usage sums exactly.
  3. The footer global total does **not** drop when a session is nuked, neither within the running process
     nor after restarting pi.
  4. Restoring a nuked session file into the sessions tree removes its ledger entry again (no double count).
  5. Missing or corrupt ledger JSON degrades to zero contribution; counter keeps working.
  6. pi startup shows **no** "does not export a valid factory function" error for the new file (it is a
     helper module in a subdirectory, not an extension).

## 5. Negative Knowledge (Guardrails & Taboos)
- **Do NOT touch:** any other extension file, pi's dist, `sessions/`, `discarded-sessions/` contents, `stats.ts` (token-counter imports `trackExtensionRun` from it — leave that import as is), the agent-dir git repo (no git commands this session per user).
- **Do NOT create a top-level `.ts` helper in `extensions/`:** pi loads every top-level `.ts`/`.js` as an extension and reports "does not export a valid factory function" for non-extensions (loader.js `loadExtension`). Helpers must live in a subdirectory WITHOUT `index.ts`/`index.js` and WITHOUT a `package.json` `pi` field.
- **Do NOT rename** `token-counter.ts` or `nuke-session.ts` (paths are tracked in the agent-dir repo and keyed in `usage-stats.json` via `trackExtensionRun(import.meta.url)`).
- **Do NOT backfill** the ledger from existing `discarded-sessions/` files: restoring such a file would double-count, and the trash layout varies per machine. Ledger starts empty (DECISION).
- **Known Pitfalls / Failed Approaches:**
  - `trash` (trash-cli) is NOT installed here → every nuke uses the `discarded-sessions/` fallback; do not assume desktop-trash paths.
  - Node 26 strips TS types but does NOT type-check; there is no `tsc` anywhere in the pi install tree → rely on `node --test` + the import smoke tests; keep the code simple and explicit.
  - Built-in `/resume`-UI session deletion is NOT covered (no pi hook for it) — counter still loses those sessions (pre-existing behavior, out of scope).
  - Concurrent pi processes: ledger writes are atomic tmp+rename, last-writer-wins on a true race (accepted; nuking is rare).
  - Nuke ordering matters: sum BEFORE discard, record AFTER discard (see `discardAndRecord`), else double- or lost-counts.
  - `sumSessionUsage` must use the exact same `usageOf` as the live scanner or the two totals drift.
