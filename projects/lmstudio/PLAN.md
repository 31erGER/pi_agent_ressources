## 1. Human Requirement (Original Intent)
Pi must be able to switch reasoning effort when calling the LM Studio (OpenAI-compatible) API — currently the effort field is missing from the JSON request, so LM Studio falls back to its server-default effort. The mapping of pi's standard effort levels to the values sent to LM Studio must live in a configuration file `~/.pi/agent/projects/lmstudio/efforts.json` (one entry per model, freely editable). Every newly loaded model that has no entry yet must get one created automatically.

## 2. Technical Architecture & Data Flow
- **Core Mechanism:** Root cause verified: `extensions/lmstudio.ts` hard-codes `compat.supportsReasoningEffort: false`, and pi's `openai-completions` `buildParams` only emits `reasoning_effort` when `options.reasoningEffort && model.reasoning && compat.supportsReasoningEffort` (value = `thinkingLevelMap[level] ?? level`; for off: `thinkingLevelMap.off` if string). Fix: the extension loads `efforts.json` (`{ [modelId]: { [piLevel]: <string|null> } }`), builds a complete `thinkingLevelMap` per model (missing level ⇒ `null` = unsupported), sets `supportsReasoningEffort: true` for reasoning-flagged models. File/mapping logic lives in a new pure, pi-free module `projects/lmstudio/lmstudio-efforts.ts` (unit-testable; project-folder convention per existing `extensions/themes.ts` → `../projects/themes/src/core.ts`); `extensions/lmstudio.ts` only wires it in.
- **Data / Control Flow:** `LM Studio /api/v0/models` → `fetchCatalog` → `chatModelIds` → `ensureModels` (read/create `efforts.json`, append `DEFAULT_ENTRY` for unknown ids, save only on change) → `toModelConfig(entry, effortsMap)` adds `thinkingLevelMap` + `supportsReasoningEffort` → pi `buildParams` → JSON body `reasoning_effort` → LM Studio.
- **Reuse & Conventions:** existing `lmstudio.ts` structure (`fetchCatalog`/`toModelConfig`/`toConfigs`/`registerProvider`/`refreshModels`), `LM_STUDIO_*` env-var convention (new: `LM_STUDIO_EFFORTS_FILE` override), `import.meta.url` path precedent from `stats.ts`, node:test style of sibling project `projects/audio-notification/test/`, pi CLI `--print --provider --model --thinking` for e2e. Default auto-created entry: `{ off: "none", minimal: "minimal", low: "low", medium: "medium", high: "high", xhigh: "xhigh", max: "xhigh" }` (LM Studio has no `max`/`off`; `xhigh` is its top level — verified live).
- **Acceptance Criteria:**
  1. `node projects/lmstudio/efforts.test.mjs` exits 0: file created when missing; entry auto-added for every unknown model id; user edits and stale (no-longer-loaded) entries preserved; no rewrite when unchanged (byte-identical); corrupt JSON ⇒ renamed to `efforts.json.corrupt-<ts>`, fresh file continues; `entryToThinkingLevelMap`: listed level → its string, missing level → `null`.
  2. E2E (`projects/lmstudio/e2e.mjs`, mock OpenAI-compatible server + real `pi --print`): JSON body of `/v1/chat/completions` contains `reasoning_effort`: no `--thinking` ⇒ `"none"`, `--thinking high` ⇒ `"high"`, `--thinking max` ⇒ `"xhigh"`.
  3. Regression: a model that does not match a reasoning pattern sends **no** `reasoning_effort` field at all.
  4. After one real `pi` run against localhost:1234, `projects/lmstudio/efforts.json` exists and contains entries for `qwen/qwen3.8-27b` (and every other catalog chat model); a user edit to the file takes effect on the next `/lmstudio` refresh without restart.

## 5. Negative Knowledge (Guardrails & Taboos)
- **Do NOT touch:** other extensions (`stats.ts`, `reload-resources.ts`, `confirmation-dialog.ts`, …), `install/releases/**` (compiled pi runtime — read-only reference), skills, and the repo's unrelated uncommitted changes (`extensions/confirmation-dialog.ts`, `skills/plan/SKILL.md`, deleted `APPEND_SYSTEM.md`).
- **Do NOT** enable effort for models with `reasoning: false` — sending `reasoning_effort` to a non-thinking model risks 400s; keep the existing pattern detection as the sole gate.
- **Do NOT** delete stale `efforts.json` entries (models not currently in the catalog may be reloaded later); only append missing ones.
- **Do NOT** overwrite a corrupt `efforts.json` in place — timestamped rename first.
- Rejected alternative: `samplingParamsByThinkingLevel` (per-level arbitrary raw params) is **not exposed** on `ProviderModelConfig` (internal `Model` field only) ⇒ `thinkingLevelMap` + `supportsReasoningEffort` is the only native path; it sends exactly `reasoning_effort`. A different parameter (e.g. `chat_template_kwargs`) would need `compat.thinkingFormat` variants — out of scope.
- Pi semantics (verified in dist 1.5.0): `xhigh`/`max` levels are selectable only when present in `thinkingLevelMap` (non-null); a `null` level is excluded from the UI and `clampThinkingLevel` never sends it; missing level in `thinkingLevelMap` would otherwise send the raw level name (hence we emit an explicit all-levels map, missing ⇒ `null`).
- E2E mock model id **must** match a reasoning pattern (`mock-thinking-model` → `/thinking/i`) or pi never sends the field.
- LM Studio rejects invalid values with an explicit error listing `none, minimal, low, medium, high, xhigh` — user edits to `efforts.json` must use those values (or LM Studio 400s); the extension deliberately does **not** client-side restrict values (server may gain levels later).
- `projects/` doubles as pi's per-project session store; the new `projects/lmstudio/` folder has no `sessions/` subdir ⇒ inert to pi, safe to coexist.
